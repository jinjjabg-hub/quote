## (a) notifyRequest 실제 동작 확인 방법

**지금 코드로 확인된 것**
- 서버 함수 notifyRequest 배포됨: 주소에 GET을 보내면 405 응답 (2026-11-12 직접 호출, 요청 문서는 만들지 않음). notifyJob, billingStatus, areaLookup도 같은 응답 (코드·호출)
- 배포 목록에 포함 (코드: .github/workflows/deploy-functions.yml)
- 웹 푸시 공개 키가 js/config.js에 들어 있음, requestNotifyUrl 설정됨 (코드)
- 고객 화면이 요청 저장 직후 notifyNewRequest를 부름. 서버는 요청이 실제로 있고, 10분 이내이고, 아직 안 알렸을 때만 1번 보냄 (코드: functions/lib/requestNotice.js)
- 알림 문구에는 고객 이름·연락처를 넣지 않음 (코드)
- 단위 테스트 있음: functions/test/requestNotice.test.mjs. 배포 워크플로가 매번 테스트를 돌림 (코드)

**아직 확인 못한 것 (미확인): 실제 폰에서 알림이 오는지**

실기기 확인 순서 (약 10분, 폰 2대 또는 폰 1대와 PC 1대)
1. 사장님 폰: Chrome에서 owner.html을 열고 Google 로그인 → 홈의 "이 휴대폰으로 알림 받기" 버튼 → 허용. 저장 위치 shops/{uid}/private/push 의 tokens에 1개 이상 생김
2. 다른 기기: 고객 링크 q.html?shop={uid}&test=1 로 요청 제출 (test=1이면 알림 제목에 [테스트]가 붙음)
3. 사장님 폰에서 10초 안에 "[테스트] 새 견적 요청이 왔어요"가 오는지 확인. 알림을 누르면 owner.html의 그 요청이 열려야 함
4. 요청 문서에 notifiedAt이 생겼는지 확인 (Firebase 콘솔 > Firestore > requests)
5. 함수 로그 확인 (Firebase 콘솔 > Functions > notifyRequest > 로그): `notifyRequest { sent: true }` 이면 성공

실패 사유 읽는 법 (로그의 reason)
| reason | 뜻 | 조치 |
|---|---|---|
| no_token | 알림 켠 기기가 없음 | 1번을 다시 (버튼을 눌러 알림 허용) |
| already | 이미 알린 요청 | 정상 (중복 방지) |
| stale | 접수 후 10분 지남 | 정상 (오래된 요청은 안 보냄) |
| failed | FCM 전송 실패 | 토큰 만료. 알림을 껐다 다시 켬 |
| origin / 403 | 허용 주소가 아닌 곳에서 호출 | quote.bizmy.net에서만 시험 |

**Play 앱(TWA)에서는 따로 확인할 것**: twa-manifest의 enableNotifications가 true여야 알림 권한이 Chrome과 연결됨 (초안은 true). 안드로이드 13 이상은 앱 설치 후 처음 알림을 켤 때 허용창이 뜨는지 확인 (미확인).

**지표 측정 한계**
- 첫 응답 시간 = sentAt − createdAt 으로 계산 가능
- 사장님이 앱 밖에서 전화·문자로 먼저 답하면 기록되지 않음
- 알림을 본 시각은 기록하지 않음. 알림이 효과가 있는지는 알림 도입 전후의 평균 발송 시간으로 비교해야 함
