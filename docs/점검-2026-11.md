# 객관 점검 (2026-11-11): 사장님이 돈을 낼 만한가

> 기준: "좋게 보기"가 아니라 **저장소의 코드·커밋 기록·문서에 있는 사실**만으로 판단했다.
> 추측은 (추측)으로 표시했다. 실제 사용 데이터(요청 수·계약 수)는 아직 없어서 **효과는 검증되지 않은 상태**다.

## 1. 한 줄 결론

계산 엔진·보안·테스트는 튼튼하다. 그런데 **사장님이 돈을 내는 이유(문의를 안 놓친다 · 견적이 빨리 나간다)에 해당하는 부분이 가장 약했고**, 아직 손님이 없는 기능(직원 일정, 평수 조회, 개발자 도구)에 코드의 절반을 썼다.

## 2. 근거 데이터

| 사실 | 숫자 | 의미 |
|---|---|---|
| 핵심 흐름(문의→견적→계약) 밖의 코드 | 화면·서버 코드 4,636줄 중 **2,167줄(47%)** 이 직원 일정·평수 조회·개발자 도구 | 1인 사장님(혼자 요금제)은 쓰지 않는 부분 |
| 평수 자동 조회 | 커밋 27개 중 **8개(30%)**, 지금도 `enabled: false` (꺼져 있음) | 고객은 한 번도 못 쓴 기능에 가장 많은 수정 |
| 새 문의 알림 (설계도 1단계·11장 "없으면 앱을 안 연다") | **미구현**이었음. 직원 일정 알림(3단계)은 구현됨 | 순서가 뒤바뀜. 1순위 지표(첫 응답 시간)를 개선할 수단이 없었음 |
| 요금 안내 페이지 | 없는 기능 4개 기재: 새 문의 알림, 계약금 결제, 직원 앱(시작·완료·사진), AI 작업시간 예측 | 표시·광고 문제 + PG 심사 페이지와 실제의 차이 |
| 요금 구조 | 설계도 12장: "고정 월정액부터 팔지 않는다(무료 10건 → 충전)" ↔ 요금 페이지: 월정액 3종 | 스스로 정한 결정과 공개 페이지가 다름 |
| 결제·요금제 제한 | 코드 없음 | 지금은 돈을 받을 방법도, 무료/유료 구분도 없음 |
| 현장 검증 | 인터뷰 1건(입주청소 1곳), 실사용 업체 0곳 | 설계도 8장의 "끝났다는 기준"(협력 업체 실제 견적 10건)을 넘긴 단계가 없음 |
| 견적 상세 화면 길이 | 휴대폰 화면 약 **10장 분량**(8,378px), 합계·발송 버튼이 맨 아래 | "확인 후 1번 눌러 발송"이 실제로는 긴 스크롤 뒤 |
| 견적 발송 | 문구 복사 → 앱 전환 → 고객 찾기 → 붙여넣기 | 고객 전화번호를 알고 있는데 활용 안 함 |
| 운영 중 업종 | 6개 중 1개(입주청소). 가입 시 업종 선택 불가 | "청소·이사·에어컨·커튼·중문" 안내와 차이 |
| 에이전트 팀 | 17명 정의, 산출물은 결정 기록 2줄·빈 양식 1개 | 조직도는 있으나 실제 작업은 이 저장소 한 줄기에서 진행됨 |

## 3. 일하는 방식의 문제와 보완

| 문제 (사실) | 왜 생겼나 | 보완 |
|---|---|---|
| 정한 순서를 건너뜀: 1단계(알림·가입 마법사·업종 선택)보다 3~4단계(직원 일정·직원 알림)를 먼저 만듦 | "끝났다는 기준"을 확인하지 않고 다음 기능으로 넘어감 | **한 번에 한 단계.** 앞 단계의 기준(실제 업체 견적 N건)을 못 넘기면 다음 기능을 시작하지 않는다 |
| 꺼져 있는 기능에 수정 8번 (평수 조회: 외부 서버 차단 문제) | 막힌 이유가 우리 코드가 아니라 바깥(공공 API·IP)인데 계속 코드로 풀려고 함 | **2번 막히면 멈추고 대안**(직접 입력)으로 출시, 원인은 따로 기록 |
| 만든 기능이 쓰이는지 모름 | 실사용 업체 0곳, 지표 시각(발송 시각 등) 미기록 | 이번에 `sentAt`·`quoteTotal` 기록 추가. **다음 기능은 협력 업체 1곳이 실제 견적 10건을 낸 뒤** 그 숫자를 보고 정한다 |
| 공개 페이지와 실제 기능이 다름 | 계획을 먼저 적고 구현이 따라오지 못함 | 공개 페이지에는 **지금 되는 것만.** 이번에 요금 안내 문구 수정 |
| 문서가 코드보다 큼 (설계도 750줄, 15장) | 미래 계획을 자세히 쓰는 데 시간을 씀 | 설계도는 유지하되, 매 작업은 "이번 단계 기준 1줄"만 확인 |
| 에이전트 17명 | 업종·기능마다 담당을 먼저 만듦 | 실제 필요는 PM·개발·검수 + 업종 지식 1명. 업종 담당은 그 업종을 **실제 업체로 검증할 때** 부른다 (quote-agents 지침에 반영) |

## 4. 이번에 고친 것

| 구분 | 내용 | 왜 (어느 지표) |
|---|---|---|
| **추가** | 새 견적 요청 → 사장님 휴대폰 알림 (`notifyRequest`) | 첫 응답 시간. 알림이 없으면 사장님은 앱을 열지 않는다 |
| **변경** | 홈을 "지금 할 일"로: 계약 요청 → 견적 대기(오래된 순) → 답 없는 견적 | 숫자 구경이 아니라 **다음 행동**을 보여줌 |
| **추가** | 답 없는 견적(발송 2일 뒤) → "문자로 다시 연락" 1탭 | 계약 전환율. 보낸 견적을 그냥 흘려보내지 않게 |
| **변경** | 이번 달 숫자: 요청 → 발송 → 계약 + **계약 금액** | 사장님이 보는 숫자는 건수가 아니라 매출 |
| **변경** | 견적 상세 맨 위에 금액 + 확인할 것(사진·위험 답변), 발송 버튼에 금액 표시 | 견적 발송 시간. 맞으면 스크롤 없이 바로 발송 |
| **변경** | 발송 후 "○○님께 문자로 보내기" 1탭 (카톡용 복사는 유지) | 견적 발송 시간 |
| **변경** | 견적서 안내 문구(조건·포함·불포함) 편집은 접어 둠 | 대부분 기본값 그대로 나감 → 화면 길이 축소 |
| **수정** | 목록 금액: 사장님이 고쳐 보낸 금액이 아니라 재계산 값이 나오던 문제 → 실제 보낸 금액 | 숫자 신뢰 |
| **제거** | 사장님 화면의 "개발자 모드"·"업종 시뮬레이터" 버튼 (운영자용. 주소 `dev.html`, `?dev=1` 은 그대로) | 사장님에게 필요 없는 메뉴 |
| **제거** | 홈의 "빠른 업무 도구"(아래 메뉴와 중복), 큰 인사말 배너 | 첫 화면을 할 일에 양보 |
| **수정** | 요금 안내의 없는 기능 4개 문구를 실제 기능으로 | 사실과 다른 안내 제거 |

## 5. 아직 안 고친 것 (결정이 필요하거나, 데이터가 먼저)

| 순위 | 할 일 | 이유 |
|---|---|---|
| 1 | **협력 업체 1곳 실사용** (실제 견적 10건) | 모든 판단의 근거. 이게 없으면 다음 기능은 전부 추측 |
| 2 | 요금 구조 확정: 설계도(무료 10건→충전)와 요금 페이지(월정액 3종) 중 하나로 | 대표 결정 사항. PG 심사 페이지와도 연결 |
| 3 | 결제 + 무료/유료 구분 | 돈을 받으려면 필수. 2번 결정 뒤 |
| 4 | 가입 직후 3분 설정(업종 선택 → 단가 확인 → 링크 복사) | 지금은 입주청소로 고정. 다른 업종 사장님은 시작 불가 |
| 5 | 고객이 견적서를 **열어봤는지** 표시 | "답 없음"과 "안 읽음"은 다른 대응이 필요 (보안 규칙 변경 필요) |
| 보류 | 평수 조회, 고객 달력, 직원 앱 확장, AI 예측 | 실사용 데이터로 필요가 확인될 때까지 추가 작업 중지 |

> 직원 일정 기능(코드 약 1,200줄)은 이미 만들어졌고 테스트도 있어 지우지 않았다. 다만 **1인 사장님에게는 "일정" 탭이 필요 없을 수 있다** (추측). 실사용 업체가 안 쓰면 팀 요금제에서만 보이게 숨기는 것을 권한다.
